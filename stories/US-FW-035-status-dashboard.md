# US-FW-035 — The public status dashboard renders the repo's own verified state

**Story:** As a Spokbot evaluator, I want a public status page
that renders the project's story, test, and verification state
from the repository's own files, so that what the project claims
about its own rigor is itself checkable instead of asserted.

**Difficulty:** 2 points.

**Tests:** `tests/statusDashboard.test.mjs` (node:test, 5 tests)
pins the generator: the page's headline counts equal the
storyLint/linkageLint summaries computed independently in the
suite, every registered story appears by id, the page is
self-contained (no external assets) and names its data source,
and story titles are HTML-escaped. The generator is
`site/build-status.mjs`; its output is `site/status.html`
(committed, regenerated by running the generator).

**Background:** Step 7 prep (public face). The kernel's story
registry and lints already measure coverage exactly (F12); the
missing piece was a public surface for those measurements. The
dashboard is deliberately a *generator*, not a hand-written page:
hand-maintained status numbers are the failure mode the whole
verification program exists to eliminate. It renders the fixture
registry (the production registry's fixture, which is what the
lints score in this tree) — when the production registry is the
lint target, the same generator points at it unchanged. No
server dependency: the output is one static HTML file with
inline CSS, at home in the existing `site/` GitHub Pages tree.

**Acceptance criteria:**

1. Given the story registry and the tree, When the generator
   runs, Then the page's story counts (total, BDD+TDD, BDD-only,
   neither, dangling references) equal the storyLint summary and
   its linkage counts equal the linkageLint summary — computed,
   never hand-written.
2. Given the registry, When the page renders, Then every
   registered story appears by id with its status, points,
   acceptance-criteria count, and test-evidence class.
3. Given the generated page, When it is served statically, Then
   it needs no server and no external assets, names the registry
   it renders, and carries its generation timestamp.
